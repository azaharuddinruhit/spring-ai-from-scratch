The order tools from the last lesson live in the support app. Parcel tracking doesn't: the shipping team owns it, in its own
service. The Model Context Protocol (MCP) lets that team publish its tools once, and any MCP client can use them. That includes
our support assistant, an IDE or a desktop chat app. This lesson builds both sides: the shipping MCP server, and the support app
as its client.

## 1. Spring mental model

MCP does for tools what JDBC does for databases. It is one protocol, and either side can be swapped. A server offers three kinds of
things:

| Server offers | Annotation (2.0.2) | Who uses it |
| --- | --- | --- |
| Tools: functions with a JSON schema | `@McpTool`, `@McpToolParam` | The model, through `ChatClient`, like any `@Tool` |
| Resources: documents addressed by a URI | `@McpResource` | The client application, which chooses what to attach |
| Prompts: message templates with arguments | `@McpPrompt`, `@McpArg` | The client application or its user |

The messages are JSON-RPC. Over Streamable HTTP, the client sends every message as a `POST` to one endpoint, `/mcp`. STDIO is the
other transport: the client starts the server as a child process and talks through its standard input and output. The client
connects at startup, lists the server's tools once and caches them. When the model asks for one of them, the client sends a
`tools/call` request.

These rules come from the 2.0.2 classes and from tests we ran against them:

- A WebMVC server without `spring.ai.mcp.server.protocol` starts the old SSE transport, which serves `/sse` and `/mcp/message`. A
  Streamable HTTP client then gets a `404` for `POST /mcp`, and with `initialized: true` (the default) the client app fails to start.
- `@McpTool` annotation hints default to `readOnlyHint = false`, `destructiveHint = true`, `idempotentHint = false` and
  `openWorldHint = true`. They describe the tool to clients; they don't enforce anything.
- `@PreAuthorize` works on an `@McpTool` method with `@EnableMethodSecurity`. A token without the scope still lists the tool, but
  calling it returns a result with `isError` and the text "Access Denied".
- A missing or rejected token fails the client's `initialize` with `McpHttpClientTransportAuthorizationException`.
- MCP tools are not added to `ChatClient` for you. Pass the auto-configured `SyncMcpToolCallbackProvider` to `defaultTools`.
- The default `ToolContextToMcpMetaConverter` copies the whole `ToolContext` into each call's `_meta`, so the server receives
  our customer id. `ToolContextToMcpMetaConverter.noOp()` sends `{}`.
- An `McpToolFilter` bean decides which listed tools reach `ChatClient`. When two connections offer a tool with the same name, the
  second one is renamed `alt_1_<name>`, with a warning.
- An `@McpPrompt` method that returns a `String` reaches the client as an `ASSISTANT` message. Return a `PromptMessage` with
  `Role.USER` for an instruction.

```java {18,19,20}
package com.example.shipping;

import org.springframework.ai.mcp.annotation.McpTool;
import org.springframework.ai.mcp.annotation.McpTool.McpAnnotations;
import org.springframework.ai.mcp.annotation.McpToolParam;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Component;

@Component
public class ShipmentTools {

    private final ShipmentRepository shipments;

    ShipmentTools(ShipmentRepository shipments) {
        this.shipments = shipments;
    }

    @McpTool(name = "track_shipment", description = "Current status, last scan and estimated delivery of a parcel",
            annotations = @McpAnnotations(readOnlyHint = true, destructiveHint = false, idempotentHint = true, openWorldHint = false))
    @PreAuthorize("hasAuthority('SCOPE_shipments.read')")
    public Shipment trackShipment(
            @McpToolParam(description = "The carrier tracking number, such as 1Z999AA10123456784") String trackingNumber) {
        return shipments.findByTrackingNumber(trackingNumber)
                .orElseThrow(() -> new IllegalArgumentException("No shipment with tracking number " + trackingNumber));
    }
```

```java {28,34,47}
package com.example.shipping;

import io.modelcontextprotocol.spec.McpSchema.PromptMessage;
import io.modelcontextprotocol.spec.McpSchema.Role;
import io.modelcontextprotocol.spec.McpSchema.TextContent;

import org.springframework.ai.mcp.annotation.McpArg;
import org.springframework.ai.mcp.annotation.McpPrompt;
import org.springframework.ai.mcp.annotation.McpResource;
import org.springframework.security.access.prepost.PreAuthorize;
import org.springframework.stereotype.Component;

/** Read-only context for the client: a document it can attach (resource) and a ready-made instruction (prompt). */
@Component
public class ShippingGuides {

    static final String DELIVERY_POLICY = """
            # Delivery policy
            A parcel is late one business day after its estimated delivery date.
            A parcel is lost when it has had no scan for 10 business days; the customer then gets a replacement.""";

    private final ShipmentRepository shipments;

    ShippingGuides(ShipmentRepository shipments) {
        this.shipments = shipments;
    }

    @McpResource(uri = "shipping://policies/delivery", name = "delivery-policy", mimeType = "text/markdown",
            description = "When a parcel counts as late or lost, and what the customer gets")
    public String deliveryPolicy() {
        return DELIVERY_POLICY;
    }

    @McpPrompt(name = "explain-delay", description = "Explain to a customer why their parcel is late")
    @PreAuthorize("hasAuthority('SCOPE_shipments.read')")
    public PromptMessage explainDelay(
            @McpArg(name = "trackingNumber", description = "The carrier tracking number", required = true) String trackingNumber) {
        Shipment shipment = shipments.findByTrackingNumber(trackingNumber)
                .orElseThrow(() -> new IllegalArgumentException("No shipment with tracking number " + trackingNumber));
        // A plain String would reach the client as an ASSISTANT message; an instruction belongs in a USER message.
        String instruction = """
                Explain to the customer, in three sentences, where parcel %s is and when it should arrive. \
                It is %s, last scanned at %s on %s, and expected on %s. Follow the delivery policy below.

                %s""".formatted(shipment.trackingNumber(), shipment.status(), shipment.lastScan(), shipment.lastScanAt(),
                shipment.estimatedDelivery(), DELIVERY_POLICY);
        return PromptMessage.builder(Role.USER, TextContent.builder(instruction).build()).build();
    }
}
```

```java {12,19}
package com.example.shipping;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.method.configuration.EnableMethodSecurity;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;

@Configuration(proxyBeanMethods = false)
@EnableMethodSecurity
class McpSecurityConfig {

    @Bean
    SecurityFilterChain mcpSecurity(HttpSecurity http) throws Exception {
        return http
                .authorizeHttpRequests(requests -> requests
                        .requestMatchers("/mcp").hasAuthority("SCOPE_mcp")
                        .anyRequest().denyAll())
                .oauth2ResourceServer(server -> server.jwt(Customizer.withDefaults()))
                .csrf(AbstractHttpConfigurer::disable) // bearer tokens only: no session cookie to forge
                .build();
    }
```

```java {27,32,41,51}
package com.example.support.mcp;

import io.modelcontextprotocol.client.transport.HttpClientStreamableHttpTransport;

import org.springframework.ai.mcp.McpToolFilter;
import org.springframework.ai.mcp.ToolContextToMcpMetaConverter;
import org.springframework.ai.mcp.customizer.McpClientCustomizer;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.http.HttpHeaders;
import org.springframework.security.oauth2.client.AuthorizedClientServiceOAuth2AuthorizedClientManager;
import org.springframework.security.oauth2.client.OAuth2AuthorizeRequest;
import org.springframework.security.oauth2.client.OAuth2AuthorizedClient;
import org.springframework.security.oauth2.client.OAuth2AuthorizedClientManager;
import org.springframework.security.oauth2.client.OAuth2AuthorizedClientService;
import org.springframework.security.oauth2.client.registration.ClientRegistrationRepository;
import org.springframework.util.Assert;

@Configuration(proxyBeanMethods = false)
@EnableConfigurationProperties(SupportMcpProperties.class)
class McpClientConfig {

    /** The default copies the whole ToolContext (our customer id included) into every MCP call's _meta. */
    @Bean
    ToolContextToMcpMetaConverter noToolContextForMcpServers() {
        return ToolContextToMcpMetaConverter.noOp();
    }

    @Bean
    McpToolFilter reviewedToolsOnly(SupportMcpProperties properties) {
        return (connection, tool) -> properties.allowedTools().contains(tool.name());
    }

    /** A connection named like an OAuth2 client registration gets that registration's token, and no other connection does. */
    @Bean
    McpClientCustomizer<HttpClientStreamableHttpTransport.Builder> accessTokenPerServer(
            ClientRegistrationRepository registrations, OAuth2AuthorizedClientManager authorizedClients) {
        return (connection, transport) -> {
            if (registrations.findByRegistrationId(connection) != null) {
                transport.addHttpRequestCustomizer((request, method, endpoint, body, context) ->
                        request.header(HttpHeaders.AUTHORIZATION, "Bearer " + accessToken(authorizedClients, connection)));
            }
        };
    }

    /** Fetches client-credentials tokens outside a web request, and reuses each one until it expires. */
    @Bean
    OAuth2AuthorizedClientManager authorizedClientManager(ClientRegistrationRepository registrations,
                                                          OAuth2AuthorizedClientService authorizedClients) {
        return new AuthorizedClientServiceOAuth2AuthorizedClientManager(registrations, authorizedClients);
    }

    private static String accessToken(OAuth2AuthorizedClientManager authorizedClients, String registrationId) {
        OAuth2AuthorizedClient client = authorizedClients.authorize(
                OAuth2AuthorizeRequest.withClientRegistrationId(registrationId).principal("support-assistant").build());
        Assert.state(client != null, () -> "No access token for MCP server " + registrationId);
        return client.getAccessToken().getTokenValue();
    }
}
```

```java {29}
package com.example.support.mcp;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.tool.ToolCallback;
import org.springframework.ai.tool.ToolCallbackProvider;

/**
 * ChatClient lists a provider's tools on every request, so an unreachable MCP server would fail every chat.
 * This answers without the MCP tools instead, and tries again on the next request.
 */
public class BestEffortToolCallbacks implements ToolCallbackProvider {

    private static final Logger log = LoggerFactory.getLogger(BestEffortToolCallbacks.class);

    private final ToolCallbackProvider delegate;

    public BestEffortToolCallbacks(ToolCallbackProvider delegate) {
        this.delegate = delegate;
    }

    @Override
    public ToolCallback[] getToolCallbacks() {
        try {
            return delegate.getToolCallbacks();
        }
        catch (RuntimeException unavailable) {
            log.warn("MCP tools unavailable, answering without them: {}", unavailable.toString());
            return new ToolCallback[0];
        }
    }
}
```

A failed token request isn't something the model can fix, so `ModelSafeToolErrors` rethrows it, as Spring AI's default processor
does:

<CodeFile title="src/main/java/com/example/support/tools/ModelSafeToolErrors.java">
```java {22}
package com.example.support.tools;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.tool.execution.ToolExecutionException;
import org.springframework.ai.tool.execution.ToolExecutionExceptionProcessor;
import org.springframework.security.oauth2.client.ClientAuthorizationException;
import org.springframework.stereotype.Component;

/** Decides what the model reads when a tool fails. Only refusals pass through; everything else is logged and replaced. */
@Component
class ModelSafeToolErrors implements ToolExecutionExceptionProcessor {

    private static final Logger log = LoggerFactory.getLogger(ModelSafeToolErrors.class);

    @Override
    public String process(ToolExecutionException exception) {
        String tool = exception.getToolDefinition().name();
        return switch (exception.getCause()) {
            case ToolRefusalException refusal -> refusal.getMessage();
            // Spring AI's default processor rethrows these too: a failed token request is not the model's problem.
            case ClientAuthorizationException authorization -> throw authorization;
            case RuntimeException failure -> {
                log.error("Tool {} failed", tool, failure);
                yield "The " + tool + " tool is unavailable right now. Say so and do not guess the answer.";
            }
            default -> throw exception;
        };
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="reliability" title="A WebMVC MCP server starts SSE unless you set the protocol">
`McpServerProperties` declares `STREAMABLE`, but the WebMVC auto-configuration starts the SSE transport when
`spring.ai.mcp.server.protocol` is missing. Streamable HTTP clients then get a `404` for `POST /mcp`. Set `protocol: STREAMABLE`
on the server, and test it with a real client, as `ShippingMcpServerTest` does.
</Gotcha>

<Gotcha kind="security" title="The default converter sends your tool context to every MCP server">
`ToolContext` holds what the model must not see, such as the customer id, and the default `ToolContextToMcpMetaConverter`
copies all of it into `_meta` on every `tools/call`. In our test, a tenant API key in the tool context reached the server this
way. Define `ToolContextToMcpMetaConverter.noOp()`, and pass a server what it needs as a tool argument it declares.
</Gotcha>

<Gotcha kind="security" title="A server can add tools without asking you">
The client lists whatever the server offers, and the model may call all of it. A tool that the server team adds next week reaches
your assistant on the next restart, with a description you never read. Keep an `McpToolFilter` allow-list of reviewed tools.
Annotation hints such as `readOnlyHint` are claims made by the server, not checks.
</Gotcha>

<Gotcha kind="security" title="Give each server its own token">
A global `McpSyncHttpClientRequestCustomizer` adds its header to every connection. In our test, one header reached two servers, so
a token for one server would be sent to every other. Use an `McpClientCustomizer<HttpClientStreamableHttpTransport.Builder>`,
which gets the connection name, and request a client-credentials token per server with only the scopes that server needs.
</Gotcha>

<Gotcha kind="reliability" title="A server that is down breaks startup, or every chat">
With `initialized: true` (the default), the client app doesn't start while a server is down or rejects the token. With
`initialized: false`, it starts, but every chat request fails, because `ChatClient` asks the tool provider for its tools on each
request. Wrap the provider so that it answers without those tools, and let `ModelSafeToolErrors` handle a server that fails
during a call.
</Gotcha>

<Gotcha kind="security" title="Tool descriptions and results are prompt text">
The model reads every tool's description and every result. A server you don't control can put instructions into either. Connect
only to servers you trust, keep the allow-list short, and treat what they return like retrieved documents: untrusted input.
</Gotcha>

<Gotcha kind="reliability" title="A STDIO server must keep its standard output clean">
Over STDIO, every line the server prints is read as a protocol message. The Boot banner and console logs break the connection:
the client logs "Error processing inbound message" and times out at startup. Set `spring.ai.mcp.server.stdio=true`,
`spring.main.web-application-type=none`, `spring.main.banner-mode=off` and an empty `logging.pattern.console`.
</Gotcha>

<Gotcha kind="migration" title="Deprecated in 2.0">
On the transport builder, `httpRequestCustomizer` is deprecated: use `addHttpRequestCustomizer`. The `ReadResourceRequest(String)`
and `GetPromptRequest(String, Map)` constructors are deprecated: use their `builder(...)` methods. SSE is the older transport;
new servers should use Streamable HTTP.
</Gotcha>

## Recap

- An MCP server offers tools, resources and prompts. Spring AI builds them from `@McpTool`, `@McpResource` and `@McpPrompt`.
- A WebMVC server needs `protocol: STREAMABLE`. Secure `/mcp` with a scope, and each tool with `@PreAuthorize`.
- On the client, pass `SyncMcpToolCallbackProvider` to `defaultTools`, filter the tools, send no tool context, and give each server
  its own token.
- Plan for a server that is down: at startup with `initialized`, and on every request with a provider that answers without it.
