The assistant can look things up. A refund is different: it moves money, so the model must not be the one who decides it. Spring
AI 2.1 can pause a tool call until a person confirms it. This lesson marks the refund tool that way, shows the customer exactly
what the model asked for, and runs the call only when the customer says yes. The rules about money stay in your code.

## 1. Spring mental model

Think of a checkout page. The shop prepares the order and shows the total; nothing is charged until the customer presses Pay,
and pressing it twice charges once. Here the model prepares the refund call, Spring AI holds it, and the customer's confirmation
is the Pay button.

These rules come from the 2.1.0 classes and from tests we ran against them:

- `@Tool(requiresConfirmation = true)` marks a tool. For tools you can't annotate, such as MCP tools, list them in
  `spring.ai.tools.confirmation.tools` or define a `ToolCallConfirmationPolicy` bean. `spring.ai.tools.confirmation.enabled`
  defaults to `true`; set to `false`, marked tools run at once and the app logs a warning at startup.
- When the model calls a marked tool, nothing runs. `ChatClient` returns the model's reply with its tool calls, and
  `ToolCallDecisions.isAwaitingDecision(response)` is `true`. A stream pauses the same way.
- The reply passes back through the advisors like any other, so the session stores it. The unanswered call stays the last
  message of the conversation until the customer decides. If the customer writes something else instead, the session first
  answers the open call with "No result was recorded for this tool call.", so the pause is closed.
- `ToolCallingManager.executeToolCalls(prompt, response, decisions)` runs the allowed calls with the prompt's tools and answers
  each denied call with your message. Every call of the reply needs a decision, the ones that didn't need confirmation too;
  a missing one throws `IllegalArgumentException`, and so does an allowed call whose tool isn't in the prompt.

Who decides what:

| Decision | Made by |
| --- | --- |
| That a refund should happen, for which order and amount | The model proposes, the customer confirms |
| Which tools wait for a person | Your `@Tool(requiresConfirmation = true)` |
| Whether the order belongs to the customer, can be refunded, and costs that amount | `RefundService`, from your data |
| That a refund pays once | The refund id: one per order, and the provider's idempotency key |

```java {20,22}
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Repository;

@Repository
public class RefundRepository {

    private final JdbcClient jdbc;

    RefundRepository(JdbcClient jdbc) {
        this.jdbc = jdbc;
    }

    /** False when the order already has a refund: the id is the primary key. */
    public boolean insertIfAbsent(Refund refund) {
        return jdbc.sql("""
                        INSERT INTO refunds (id, customer_id, order_number, amount, reason)
                        VALUES (:id, :customerId, :orderNumber, :amount, :reason)
                        ON CONFLICT (id) DO NOTHING""")
                .paramSource(refund)
                .update() == 1;
    }
}
```

The customer confirms what the model asked for, and the model can ask for anything. So the service checks the call again: the
order must belong to the signed-in customer, be shipped or delivered, and the amount must be its total. If the payment call
throws, the transaction rolls back the insert, and a later confirmation pays with the same idempotency key:

```java {35,41,45,48,54}
package com.example.support.refund;

import java.math.BigDecimal;
import java.nio.charset.StandardCharsets;
import java.util.EnumSet;
import java.util.Set;
import java.util.UUID;

import com.example.support.order.Order;
import com.example.support.order.OrderRepository;
import com.example.support.order.OrderStatus;
import com.example.support.tools.ToolRefusalException;

import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

/** Runs only after the customer confirmed the call, and checks it again: the model chose the arguments. */
@Service
public class RefundService {

    private static final Set<OrderStatus> REFUNDABLE = EnumSet.of(OrderStatus.SHIPPED, OrderStatus.DELIVERED);

    private final OrderRepository orders;
    private final RefundRepository refunds;
    private final PaymentClient payments;

    RefundService(OrderRepository orders, RefundRepository refunds, PaymentClient payments) {
        this.orders = orders;
        this.refunds = refunds;
        this.payments = payments;
    }

    @Transactional
    public Refund refund(String customerId, String orderNumber, BigDecimal amount, String reason) {
        Order order = orders.findForCustomer(customerId, orderNumber)
                .orElseThrow(() -> new ToolRefusalException("This customer has no order " + orderNumber + "."));
        if (!REFUNDABLE.contains(order.status())) {
            throw new ToolRefusalException("Order " + orderNumber + " is " + order.status() + " and cannot be refunded.");
        }
        // The customer confirmed this amount, so it must be the order total, not a number the model made up.
        if (amount.compareTo(order.total()) != 0) {
            throw new ToolRefusalException("Order " + orderNumber + " can only be refunded in full, " + order.total() + ".");
        }
        Refund refund = new Refund(refundId(orderNumber), customerId, orderNumber, order.total(), reason);
        if (!refunds.insertIfAbsent(refund)) {
            throw new ToolRefusalException("Order " + orderNumber + " has already been refunded.");
        }
        payments.refund(orderNumber, refund.amount(), refund.id());
        return refund;
    }

    /** One id per order, so a second refund of the order fails to insert and the provider sees the same key. */
    static UUID refundId(String orderNumber) {
        return UUID.nameUUIDFromBytes(("refund:" + orderNumber).getBytes(StandardCharsets.UTF_8));
    }
}
```

```java {16,19}
record SupportTools(OrderTools orders, RefundTools refunds, ToolCallbackProvider shipping) {

    ToolCallback[] callbacks() {
        return Stream.concat(Stream.of(ToolCallbacks.from(orders, refunds)), Stream.of(shipping.getToolCallbacks()))

    }
```

```java {62,68,71,78,81,101,113}
package com.example.support.chat;

import java.nio.charset.StandardCharsets;
import java.util.List;
import java.util.Locale;
import java.util.Optional;
import java.util.UUID;
import java.util.function.Consumer;

import com.example.support.knowledge.KnowledgeFilters;
import com.example.support.tools.CustomerToolContext;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.messages.Message;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.model.tool.ToolCallDecision;
import org.springframework.ai.model.tool.ToolCallDecisions;
import org.springframework.ai.model.tool.ToolCallLimitExceededException;
import org.springframework.ai.model.tool.ToolCallingChatOptions;
import org.springframework.ai.model.tool.ToolCallingManager;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.session.SessionService;
import org.springframework.ai.session.advisor.SessionAdvisors;
import org.springframework.stereotype.Service;

@Service
public class SupportChatService {

    static final String TOOL_LIMIT_ANSWER = "I couldn't finish looking that up. A support agent will follow up in this chat.";
    static final String CONFIRMATION_ANSWER = "Please confirm or decline this in the app.";
    static final String DECLINED = "The customer declined.";

    private static final Logger log = LoggerFactory.getLogger(SupportChatService.class);

    private final ChatClient supportChatClient;
    private final SessionService sessionService;
    private final ToolCallingManager toolCallingManager;
    private final SupportTools tools;

    public SupportChatService(ChatClient supportChatClient, SessionService sessionService,
                              ToolCallingManager toolCallingManager, SupportTools tools) {
        this.supportChatClient = supportChatClient;
        this.sessionService = sessionService;
        this.toolCallingManager = toolCallingManager;
        this.tools = tools;
    }

    public String ask(String userId, UUID chatId, String product, String question, Locale language) {
        return answer(userId, chatId, language, request -> request
                .user(question)
                // Replaces the retriever's default filter, so it must keep the audience condition.
                .advisors(advisor -> advisor.param(VectorStoreDocumentRetriever.FILTER_EXPRESSION,
                        KnowledgeFilters.customerDocuments(product))));
    }

    /** The tool calls waiting for the customer's decision: the session's last message, when it is an unanswered call. */
    public List<AssistantMessage.ToolCall> awaitingConfirmation(String userId, UUID chatId) {
        return pausedReply(sessionId(userId, chatId)).map(AssistantMessage::getToolCalls).orElse(List.of());
    }

    /** Runs the calls the customer confirmed, or tells the model they declined, and returns the model's answer. */
    public String confirm(String userId, UUID chatId, boolean approved, Locale language) {
        AssistantMessage paused = pausedReply(sessionId(userId, chatId)).orElseThrow(NothingToConfirmException::new);
        // Every call of the reply needs a decision, the ones that didn't need confirmation too.
        var decisions = new ToolCallDecisions(ToolCallDecisions.toolCallKeys(paused).stream()
                .map(key -> approved ? ToolCallDecision.allow(key) : ToolCallDecision.deny(key, DECLINED))
                .toList());
        var options = ToolCallingChatOptions.builder()
                .toolCallbacks(tools.callbacks())
                .toolContext(CustomerToolContext.of(userId))
                .build();
        List<Message> history = toolCallingManager
                .executeToolCalls(new Prompt(List.of(), options), new ChatResponse(List.of(new Generation(paused))), decisions)
                .conversationHistory();
        // The session holds the question and the paused reply; send only the tool results.
        return answer(userId, chatId, language, request -> request.messages(history.getLast()));
    }

    public void forget(String userId, UUID chatId) {
        sessionService.delete(sessionId(userId, chatId));
    }

    private String answer(String userId, UUID chatId, Locale language, Consumer<ChatClient.ChatClientRequestSpec> request) {
        ChatClient.ChatClientRequestSpec spec = supportChatClient.prompt()
                .toolContext(CustomerToolContext.of(userId))
                .advisors(SessionAdvisors.session(sessionId(userId, chatId)))
                .advisors(advisor -> advisor
                        .param(TokenBudgetAdvisor.USER_ID, userId)
                        .param(AnswerLanguageAdvisor.LANGUAGE, language));
        request.accept(spec);
        ChatResponse response = spec.call().chatResponse();
        Generation answer = response == null ? null : response.getResult();
        if (answer == null) {
            throw new IllegalStateException("The model returned no answer");
        }
        if (ToolCallDecisions.isAwaitingDecision(response)) {
            return CONFIRMATION_ANSWER;
        }
        if (ToolCallLimitExceededException.FINISH_REASON.equals(answer.getMetadata().getFinishReason())) {
            log.warn("Tool call limit reached for {}: {}", userId, answer.getOutput().getText());
            return TOOL_LIMIT_ANSWER;
        }
        return answer.getOutput().getText();
    }

    private Optional<AssistantMessage> pausedReply(String sessionId) {
        List<Message> messages = sessionService.findById(sessionId) == null ? List.of() : sessionService.getMessages(sessionId);
        return messages.isEmpty() || !(messages.getLast() instanceof AssistantMessage reply) || !reply.hasToolCalls()
                ? Optional.empty()
                : Optional.of(reply);
    }

    /** A session id that only this user's chat maps to, so a chat id alone never reaches another user's session. */
    static String sessionId(String userId, UUID chatId) {
        return UUID.nameUUIDFromBytes((userId + ":" + chatId).getBytes(StandardCharsets.UTF_8)).toString();
    }
}
```

```java {28,29}
package com.example.support.chat;

import java.util.Map;
import java.util.regex.Pattern;

import org.springframework.ai.chat.client.ChatClientRequest;
import org.springframework.ai.chat.client.ChatClientResponse;
import org.springframework.ai.chat.client.advisor.api.AdvisorChain;
import org.springframework.ai.chat.client.advisor.api.BaseAdvisor;
import org.springframework.ai.chat.messages.UserMessage;
import org.springframework.core.Ordered;

/** Masks e-mail addresses and card numbers in the user message before memory, logs or the model see it. */
public final class PiiRedactionAdvisor implements BaseAdvisor {

    private static final Map<Pattern, String> RULES = Map.of(
            Pattern.compile("[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\\.[A-Za-z]{2,}"), "[email]",
            Pattern.compile("\\b(?:\\d[ -]?){12,18}\\d\\b"), "[card]");

    @Override
    public int getOrder() {
        // Before memory (+200), so the conversation is stored already redacted.
        return Ordered.HIGHEST_PRECEDENCE + 100;
    }

    @Override
    public ChatClientRequest before(ChatClientRequest request, AdvisorChain chain) {
        // A confirmation resumes with tool results and no new message; augmentUserMessage would append one after them.
        if (!(request.prompt().getInstructions().getLast() instanceof UserMessage)) {
            return request;
        }
        return request.mutate()
                .prompt(request.prompt().augmentUserMessage(user -> user.mutate().text(redact(user.getText())).build()))
                .build();
    }

    @Override
    public ChatClientResponse after(ChatClientResponse response, AdvisorChain chain) {
        return response;
    }

    static String redact(String text) {
        String result = text;
```

## 4. Production gotchas & security

<Gotcha kind="security" title="A confirmation is not a check">
The customer confirms the arguments the model chose, and the model chose them from whatever the customer typed. "Make it 500.00"
becomes a 500.00 refund call that a hurried customer approves. Keep the money rules in the service: the owner from the tool
context, the status and the amount from your own data.
</Gotcha>

<Gotcha kind="reliability" title="Confirm once, pay once">
Two clicks, a retry or two browser tabs can resume the same call. One refund id per order makes the second insert do nothing,
and the same id as the provider's idempotency key covers a retry after the payment went through. Return `409` when nothing waits
in the customer's own chat, so another customer's pending call isn't revealed.
</Gotcha>

<Gotcha kind="reliability" title="Decide on every call of the reply">
A reply can carry several tool calls, and only some of them may need confirmation. `executeToolCalls` throws unless each call has
a decision, so build them from `ToolCallDecisions.toolCallKeys(reply)`, and pass the tools the allowed calls need in the prompt.
</Gotcha>

<Gotcha kind="migration" title="Coming from 2.0">
2.0 had no confirmation step. The usual way out was a tool that only proposed the action, a status column and a separate
confirmation endpoint, because stopping the call with `toolExecutionEligibilityChecker` left an unanswered tool call in
`ChatMemory`. In 2.1 the pause is a normal reply that the session stores and closes, so the proposal table can go.
</Gotcha>

## Recap

- `@Tool(requiresConfirmation = true)` makes Spring AI stop before the call runs and return the reply with its tool calls.
- The session keeps the waiting call. Show its arguments, then resume with `ToolCallingManager.executeToolCalls(prompt, response,
  decisions)` and send the tool results through the chat client.
- The customer confirms what the model asked for, so the service still checks the owner, the status and the amount.
- One refund id per order, inserted with `ON CONFLICT DO NOTHING` and passed as the idempotency key, pays once.
