**You'll need:** the support app from Module 4 and a chat model that calls tools. Nothing new outside Spring AI.

The support assistant answers from the knowledge base, but it can't see a customer's orders. "Where is my order 1042?" needs
data that lives in your database. With tool calling, the model asks your application to run a method, reads the result and then
answers. The model only asks. Your code decides which tools exist, whose data they read and when the loop stops.

## 1. Spring mental model

A tool works like a controller method that the model calls instead of a browser. `@Tool` marks the method. Its description is the
documentation the model reads. Spring AI turns the parameters into a JSON schema, much as springdoc does for a `@RequestBody`.
`ToolCallingAdvisor` plays the `DispatcherServlet` part: it receives the model's tool calls, runs the matching methods and sends
the results back.

<Mermaid

  M -->|"tool calls"| X["ToolCallingManager<br/>runs each tool"]

  X -->|"limit reached"| L["finish reason<br/>toolCallLimitExceeded"]

These rules come from the 2.1.0 classes and from tests we ran against them:

- `ChatClient` registers `ToolCallingAdvisor` itself, at `HIGHEST_PRECEDENCE + 300`. Every model call in the loop sends the whole
  exchange so far, including earlier tool calls and their results. Advisors ordered after it run once per model call (Module 3).
- A `ToolContext` parameter is left out of the schema, so the model can't see it or set it. A parameter with `@ToolParam` is
  part of the schema, and the model fills it with whatever it reads in the conversation.
- The return value goes back to the model as JSON. A record becomes a JSON object.
- When a tool throws, a `ToolExecutionExceptionProcessor` decides what the model reads. The default one sends the exception
  message. A bean of your own replaces it.
- `spring.ai.tools.limits` caps the loop: `max-calls-per-tool-default` (40), `max-calls-per-tool` per tool name,
  `max-total-tool-calls` (150) and `excluded-tools`. `-1` turns a limit off.
- With `on-limit-exceeded: THROW` (the default), the call that would go over the limit doesn't run. The advisor stops the loop and
  returns one generation, with finish reason `toolCallLimitExceeded` and the limit message as its text, such as "Tool call limit
  (3) exceeded for tool 'findOrder'. No further calls to this tool are allowed in this turn." With a limit of 3, the model is
  called four times. `RETURN_ERROR_RESPONSE` sends that message to the model as the tool's result instead, and the loop goes on.
- `defaultTools(Object...)` and `tools(Object...)` take `@Tool` objects, `ToolCallback`s and `ToolCallbackProvider`s.
  `defaultToolCallbacks` and `toolCallbacks` are deprecated for removal in 2.0.

Who decides what:

| Decision | Made by |
| --- | --- |
| Whether to call a tool, which one, and with which arguments | The model |
| Which tools exist and what each description says | Your `@Tool` methods |
| Whose data a tool reads | `ToolContext`, set by your service from the signed-in user |
| What the model reads when a tool fails | Your `ToolExecutionExceptionProcessor` |
| When the loop stops | `spring.ai.tools.limits`, then your service reads the finish reason |

```java {20}
package com.example.support.tools;

import java.util.Map;

import org.springframework.ai.chat.model.ToolContext;

/** The signed-in customer, handed to tools by the application. The model never sees or sets it. */
public final class CustomerToolContext {

    private static final String CUSTOMER_ID = "customerId";

    private CustomerToolContext() {
    }

    public static Map<String, Object> of(String customerId) {
        return Map.of(CUSTOMER_ID, customerId);
    }

    public static String customerId(ToolContext context) {
        if (context.getContext().get(CUSTOMER_ID) instanceof String customerId) {
            return customerId;
        }
        throw new IllegalStateException("No customer in the tool context");
    }
}
```

```java {24,26,30,32}
package com.example.support.order;

import static com.example.support.tools.CustomerToolContext.customerId;

import java.util.List;

import com.example.support.tools.ToolRefusalException;

import org.springframework.ai.chat.model.ToolContext;
import org.springframework.ai.tool.annotation.Tool;
import org.springframework.ai.tool.annotation.ToolParam;
import org.springframework.stereotype.Component;

/** Order lookups for the assistant. The customer comes from the tool context, never from the model. */
@Component
public class OrderTools {

    private final OrderRepository orders;

    public OrderTools(OrderRepository orders) {
        this.orders = orders;
    }

    @Tool(description = "Find one of the signed-in customer's orders by its order number")
    Order findOrder(@ToolParam(description = "The order number, such as 1042") String orderNumber, ToolContext context) {
        return orders.findForCustomer(customerId(context), orderNumber)
                .orElseThrow(() -> new ToolRefusalException("This customer has no order " + orderNumber + "."));
    }

    @Tool(description = "List the signed-in customer's most recent orders, newest first")
    List<Order> recentOrders(@ToolParam(description = "How many orders to return, from 1 to 10") int count, ToolContext context) {
        return orders.findRecentForCustomer(customerId(context), Math.clamp(count, 1, 10));
    }
}
```

This processor replaces the default one. It passes refusals through and replaces every other failure with a sentence that leaks
nothing:

<CodeFile title="src/main/java/com/example/support/tools/ModelSafeToolErrors.java">
```java {19,22}
package com.example.support.tools;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.tool.execution.ToolExecutionException;
import org.springframework.ai.tool.execution.ToolExecutionExceptionProcessor;
import org.springframework.stereotype.Component;

/** Decides what the model reads when a tool fails. Only refusals pass through; everything else is logged and replaced. */
@Component
class ModelSafeToolErrors implements ToolExecutionExceptionProcessor {

    private static final Logger log = LoggerFactory.getLogger(ModelSafeToolErrors.class);

    @Override
    public String process(ToolExecutionException exception) {
        String tool = exception.getToolDefinition().name();
        return switch (exception.getCause()) {
            case ToolRefusalException refusal -> refusal.getMessage();
            case RuntimeException failure -> {
                log.error("Tool {} failed", tool, failure);
                yield "The " + tool + " tool is unavailable right now. Say so and do not guess the answer.";
            }
            default -> throw exception;
        };
    }
}
```

```java {31}
package com.example.support.knowledge;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.generation.augmentation.ContextualQueryAugmenter;
import org.springframework.ai.rag.preretrieval.query.transformation.CompressionQueryTransformer;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.Ordered;

@Configuration(proxyBeanMethods = false)
class KnowledgeRagConfig {

    @Bean
    RetrievalAugmentationAdvisor knowledgeRagAdvisor(ChatClient.Builder builder, VectorStore vectorStore) {
        return RetrievalAugmentationAdvisor.builder()
                // Turns a follow-up such as "and for gift cards?" into a standalone question, using the history.
                .queryTransformers(CompressionQueryTransformer.builder()
                        .chatClientBuilder(builder)
                        .build())
                .documentRetriever(VectorStoreDocumentRetriever.builder()
                        .vectorStore(vectorStore)
                        .topK(5)
                        .similarityThreshold(0.5)
                        .filterExpression(KnowledgeFilters.customerDocuments()) // when a call passes no filter
                        .build())
                // An order question finds no documents. The default would then replace it with a refusal, and the model
                // would never call a tool. The system prompt keeps policy answers to the documents instead.
                .queryAugmenter(ContextualQueryAugmenter.builder().allowEmptyContext(true).build())
                // After memory (+ 210), so memory stores the question rather than the augmented prompt,
                // and before tool calling (+ 300), so it retrieves once per question.
                .order(Ordered.HIGHEST_PRECEDENCE + 225)
                .build();
    }
}
```

```java {39,52}
package com.example.support.chat;

import java.nio.charset.StandardCharsets;
import java.util.Locale;
import java.util.UUID;

import com.example.support.knowledge.KnowledgeFilters;
import com.example.support.tools.CustomerToolContext;

import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.model.tool.ToolCallLimitExceededException;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.session.SessionService;
import org.springframework.ai.session.advisor.SessionAdvisors;
import org.springframework.stereotype.Service;

@Service
public class SupportChatService {

    static final String TOOL_LIMIT_ANSWER = "I couldn't finish looking that up. A support agent will follow up in this chat.";

    private static final Logger log = LoggerFactory.getLogger(SupportChatService.class);

    private final ChatClient supportChatClient;
    private final SessionService sessionService;

    public SupportChatService(ChatClient supportChatClient, SessionService sessionService) {
        this.supportChatClient = supportChatClient;
        this.sessionService = sessionService;
    }

    public String ask(String userId, UUID chatId, String product, String question, Locale language) {
        ChatResponse response = supportChatClient.prompt()
                .user(question)
                .toolContext(CustomerToolContext.of(userId))
                .advisors(SessionAdvisors.session(sessionId(userId, chatId)))
                .advisors(advisor -> advisor
                        .param(TokenBudgetAdvisor.USER_ID, userId)
                        .param(AnswerLanguageAdvisor.LANGUAGE, language)
                        // Replaces the retriever's default filter, so it must keep the audience condition.
                        .param(VectorStoreDocumentRetriever.FILTER_EXPRESSION, KnowledgeFilters.customerDocuments(product)))
                .call()
                .chatResponse();
        Generation answer = response == null ? null : response.getResult();
        if (answer == null) {
            throw new IllegalStateException("The model returned no answer");
        }
        if (ToolCallLimitExceededException.FINISH_REASON.equals(answer.getMetadata().getFinishReason())) {
            log.warn("Tool call limit reached for {}: {}", userId, answer.getOutput().getText());
            return TOOL_LIMIT_ANSWER;
        }
        return answer.getOutput().getText();
    }

    public void forget(String userId, UUID chatId) {
        sessionService.delete(sessionId(userId, chatId));
    }

    /** A session id that only this user's chat maps to, so a chat id alone never reaches another user's session. */
    static String sessionId(String userId, UUID chatId) {
        return UUID.nameUUIDFromBytes((userId + ":" + chatId).getBytes(StandardCharsets.UTF_8)).toString();
    }
}
```

```java {28}
package com.example.support;

import java.util.List;
import java.util.concurrent.CopyOnWriteArrayList;
import java.util.function.Function;

import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.model.ChatModel;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.chat.prompt.ChatOptions;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.model.tool.ToolCallingChatOptions;

/** A chat model that answers from a script and records every prompt. Its options accept tools, like a real provider's. */
public class ScriptedChatModel implements ChatModel {

    private final Function<Prompt, AssistantMessage> script;
    private final List<Prompt> prompts = new CopyOnWriteArrayList<>(); // workers call it from several threads

    public ScriptedChatModel(Function<Prompt, AssistantMessage> script) {
        this.script = script;
    }

    public static AssistantMessage toolCall(String name, String arguments) {
        return AssistantMessage.builder()
                .content("")
                .toolCalls(List.of(new AssistantMessage.ToolCall("call-" + name, "function", name, arguments)))
                .build();
    }

    @Override
    public ChatResponse call(Prompt prompt) {
        prompts.add(prompt);
        return new ChatResponse(List.of(new Generation(script.apply(prompt))));
    }

    @Override
    public ChatOptions getOptions() {
        return ToolCallingChatOptions.builder().build();
    }

    public List<Prompt> prompts() {
        return prompts;
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="security" title="Never let the model choose whose data a tool reads">
A `@ToolParam String customerId` is filled by the model, from anything in the conversation, including "my husband's id is bob" or
text in a retrieved document. Take identity from the signed-in user, pass it with `.toolContext(...)`, and filter every query by
it. A test that checks the tool's input schema for `customer` keeps it that way.
</Gotcha>

<Gotcha kind="reliability" title="A limit ends the loop with a technical message as the answer">
With the default `THROW`, `.content()` returns "Tool call limit (3) exceeded for tool 'findOrder'. No further calls to this tool
are allowed in this turn." No exception is thrown. Read the finish reason and compare it with
`ToolCallLimitExceededException.FINISH_REASON`, as `SupportChatService` does, or the customer reads the limit message.
</Gotcha>

<Gotcha kind="security" title="Keep tools that change things out of the model's reach">
The model calls a tool whenever the conversation makes it seem right, and the conversation can include a customer's
instructions or a poisoned document. Read-only tools scoped to the signed-in customer are safe to expose. A tool that refunds,
cancels or deletes should wait until the customer confirms it. Lesson 3 marks the refund tool with `requiresConfirmation`.
</Gotcha>

<MoreGotchas>

<Gotcha kind="security" title="The default processor sends exception messages to the model">
`DefaultToolExecutionExceptionProcessor` returns the exception message as the tool result. For a JDBC failure that is your SQL,
table and column names, and host names, and the model may repeat them to the customer. Define one
`ToolExecutionExceptionProcessor` bean that passes only messages written for the model and logs the rest.
</Gotcha>

<Gotcha kind="cost" title="Every tool round is another full model call">
Each round sends the whole exchange again: system prompt, memory, retrieved documents, every tool definition and every earlier
result. The defaults of 40 calls per tool and 150 per question are far more than a support question needs. Set limits near
what a real question takes, and keep tool results small: return a record with the fields the model needs, not the whole entity.
</Gotcha>

<Gotcha kind="cost" title="Many tools mean a long prompt on every call">
Every tool definition goes with every model call. With dozens of tools, consider `ToolSearchToolCallingAdvisor`
(`spring-ai-starter-tool-search-advisor`, enabled with `spring.ai.chat.client.tool-search-advisor.enabled=true`). It sends only a
`toolSearchTool` at first, then adds the tools the model's searches find. In our test, a scripted model searched for "order" and the next
call carried `findOrder` and `toolSearchTool`. It keeps the found tools per conversation, under the id that
`SessionAdvisors.session(...)` sets, and fails without one. The <a href={lessonHref('05-tools-mcp-agents/tool-search')}>Tool
Search</a> lesson measures its indexes.
</Gotcha>

<Gotcha kind="migration" title="defaultToolCallbacks is deprecated for removal">
In 2.0, `defaultToolCallbacks(...)` and `toolCallbacks(...)` are deprecated for removal. `defaultTools(...)` and `tools(...)`
accept `@Tool` objects, `ToolCallback`s and `ToolCallbackProvider`s, so one call registers all of them.
</Gotcha>

</MoreGotchas>

## Recap

- `@Tool` methods are what the model may call. `ToolCallingAdvisor` (`+ 300`) runs the loop, and each round is a full model call.
- A `ToolContext` parameter is invisible to the model. Use it for identity, and filter every query by it.
- A `ToolExecutionExceptionProcessor` bean decides what the model reads when a tool fails. Pass only messages written for it.
- `spring.ai.tools.limits` caps the loop. With the default `THROW`, check the finish reason `toolCallLimitExceeded` and answer with
  your own text.
