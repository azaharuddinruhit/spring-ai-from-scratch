**You'll need:** the support app from the MCP lesson, structured output from Module 2, and Java's virtual threads.

A support ticket with several questions needs more than one tool loop. It needs several steps: split it, answer each part, merge
the answers, then check the result. This lesson builds that workflow. Spring AI 2.1.0 has no workflow engine, and it doesn't need
one: each step is a `ChatClient` call, and plain Java connects the steps.

## 1. Spring mental model

Think of Spring Batch or Spring Integration. Your code defines the flow, and each step does one job. A **workflow** keeps the
control flow in code and asks the model to fill in each step. An **agent** lets the model choose the next step, which is what
the tool loop from lesson 1 does. Use a workflow when you know the steps. It is cheaper, it can be tested step by step, and it
can't wander.

| Pattern | What the code does | In this lesson |
| --- | --- | --- |
| Orchestrator | One call plans the work as structured output | The planner returns a `Plan` with `entity(Plan.class)` |
| Routing | Code sends each input to a specialised client | One writer `ChatClient` per `Department` |
| Parallel workers | Independent calls run at the same time | Writers run on virtual threads |
| Evaluator-optimizer | A reviewer checks the result; an editor fixes it, up to a limit | `Review`, then a revision, at most `MAX_ROUNDS` times |

The previous lesson's refund is a fifth pattern, a human in the loop: the model asks for an action, and it runs only once a person confirms it.

These rules come from the 2.1.0 classes and from tests we ran against them:

- `ChatClient.Builder.clone()` copies the auto-configured builder, so each role gets its own system prompt on the same model.
- A `ChatModel` called from virtual threads must be thread-safe. Our test model records prompts in a `CopyOnWriteArrayList` for
  that reason.

- Pick **Two issues**. The billing writer promises a refund date, the reviewer catches it, and the editor revises the reply in

- Pick **Five issues**. The fifth issue is never sent, because the plan is capped at four. The reviewer keeps objecting, so

```java {74,76,91,105}
package com.example.support.ticket;

import java.util.EnumSet;
import java.util.List;
import java.util.Map;
import java.util.Objects;
import java.util.concurrent.CompletableFuture;
import java.util.concurrent.ExecutorService;
import java.util.concurrent.Executors;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.util.Assert;

/**
 * Three workflow patterns in one: a planner splits the ticket into issues (orchestrator), each issue goes to its
 * department's writer (routing) and the writers run in parallel (workers); then a reviewer sends the merged reply back
 * to the editor until it approves, at most {@value #MAX_ROUNDS} times (evaluator-optimizer). The code owns the control
 * flow; the model fills in each step.
 */
public class TicketReplyService {

    static final int MAX_ISSUES = 4;
    static final int MAX_ROUNDS = 3;

    private static final String ANSWER = """
            Answer only this part of the ticket: {question}

            The whole ticket, for context:
            {ticket}""";

    private static final String MERGE = """
            Merge these answers into one reply to the ticket, in the order given.

            Ticket:
            {ticket}

            Answers:
            {answers}""";

    private static final String REVIEW = """
            Ticket:
            {ticket}

            Draft reply:
            {reply}""";

    private static final String REVISE = """
            Rewrite this reply so that it fixes every problem listed.

            Ticket:
            {ticket}

            Reply:
            {reply}

            Problems:
            {problems}""";

    private final ChatClient planner;
    private final Map<Department, ChatClient> writers;
    private final ChatClient editor;
    private final ChatClient reviewer;

    TicketReplyService(ChatClient planner, Map<Department, ChatClient> writers, ChatClient editor, ChatClient reviewer) {
        Assert.isTrue(writers.keySet().containsAll(EnumSet.allOf(Department.class)), "Every department needs a writer");
        this.planner = planner;
        this.writers = Map.copyOf(writers);
        this.editor = editor;
        this.reviewer = reviewer;
    }

    public ReplyDraft draftReply(String subject, String body) {
        String ticket = "Subject: " + subject + "\n\n" + body;
        Plan plan = Objects.requireNonNull(planner.prompt().user(ticket).call().entity(Plan.class), "No plan");
        // The model decides how many workers run, so cap the fan-out.
        List<Issue> issues = plan.issues().stream().limit(MAX_ISSUES).toList();
        Assert.state(!issues.isEmpty(), "The planner found no issue in the ticket");

        List<String> answers = answerInParallel(ticket, issues);
        String reply = answers.size() == 1 ? answers.getFirst() : editor.prompt()
                .user(user -> user.text(MERGE).param("ticket", ticket).param("answers", String.join("\n\n---\n\n", answers)))
                .call()
                .content();

        for (int round = 1; ; round++) {
            String draft = reply;
            Review review = Objects.requireNonNull(reviewer.prompt()
                    .user(user -> user.text(REVIEW).param("ticket", ticket).param("reply", draft))
                    .call()
                    .entity(Review.class), "No review");
            if (review.approved() || round == MAX_ROUNDS) {
                return new ReplyDraft(issues.stream().map(Issue::department).distinct().toList(), draft, round, !review.approved());
            }
            reply = editor.prompt()
                    .user(user -> user.text(REVISE)
                            .param("ticket", ticket)
                            .param("reply", draft)
                            .param("problems", "- " + String.join("\n- ", review.problems())))
                    .call()
                    .content();
        }
    }

    private List<String> answerInParallel(String ticket, List<Issue> issues) {
        try (ExecutorService workers = Executors.newVirtualThreadPerTaskExecutor()) {
            List<CompletableFuture<String>> answers = issues.stream()
                    .map(issue -> CompletableFuture.supplyAsync(() -> writers.get(issue.department()).prompt()
                            .user(user -> user.text(ANSWER).param("question", issue.question()).param("ticket", ticket))
                            .call()
                            .content(), workers))
                    .toList();
            return answers.stream().map(CompletableFuture::join).toList();
        }
    }
}
```

```java {27}
package com.example.support.ticket;

import java.util.EnumMap;
import java.util.Map;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration(proxyBeanMethods = false)
class TicketWorkflowConfig {

    private static final Map<Department, String> WRITERS = Map.of(
            Department.BILLING, """
                    You answer billing questions for Acme Cloud: invoices, charges and refunds. \
                    Never promise a refund: refunds are proposed in the app and the customer confirms them.""",
            Department.TECHNICAL, """
                    You answer technical questions for Acme Cloud: outages, errors and configuration. \
                    Ask for the request id or logs when the ticket has none.""",
            Department.ACCOUNT, """
                    You answer account questions for Acme Cloud: sign-in, users and plans. \
                    You cannot change an account; explain the steps the customer takes.""");

    @Bean
    TicketReplyService ticketReplyService(ChatClient.Builder builder) {
        Map<Department, ChatClient> writers = new EnumMap<>(Department.class);
        WRITERS.forEach((department, instructions) -> writers.put(department, builder.clone().defaultSystem(instructions).build()));

        ChatClient planner = builder.clone()
                .defaultSystem("""
                        Split an Acme Cloud support ticket into its separate issues, at most four, and give each one \
                        to the department that handles it. Phrase each issue as a question.""")
                .build();
        ChatClient editor = builder.clone()
                .defaultSystem("You edit Acme Cloud support replies: one greeting, one sign-off, plain sentences, nothing invented.")
                .build();
        ChatClient reviewer = builder.clone()
                .defaultSystem("""
                        You check support replies before an agent sends them. Approve a reply only if it answers every \
                        issue in the ticket, promises no refund, credit or date, and contains no internal notes. \
                        Otherwise list each problem in one sentence.""")
                .build();
        return new TicketReplyService(planner, writers, editor, reviewer);
    }
}
```

```java {18}
package com.example.support.security;

import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.security.config.Customizer;
import org.springframework.security.config.annotation.web.builders.HttpSecurity;
import org.springframework.security.config.annotation.web.configurers.AbstractHttpConfigurer;
import org.springframework.security.config.http.SessionCreationPolicy;
import org.springframework.security.web.SecurityFilterChain;

@Configuration(proxyBeanMethods = false)
public class SecurityConfig {

    @Bean
    SecurityFilterChain apiSecurity(HttpSecurity http) throws Exception {
        return http
                .authorizeHttpRequests(requests -> requests
                        .requestMatchers("/api/tickets/**").hasAuthority("SCOPE_support.agent") // agents, not customers
                        .anyRequest().authenticated())
                .oauth2ResourceServer(server -> server.jwt(Customizer.withDefaults()))
                .sessionManagement(session -> session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))
                .csrf(AbstractHttpConfigurer::disable) // bearer tokens only: no session cookie to forge
                .build();
    }
}
```

```java {64,101}
package com.example.support.ticket;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.assertThatThrownBy;

import java.util.Iterator;
import java.util.List;
import java.util.Map;
import java.util.stream.Collectors;

import com.example.support.ScriptedChatModel;

import org.junit.jupiter.api.Test;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.AssistantMessage;

class TicketReplyServiceTest {

    private static final String APPROVED = """
            {
              "approved": true,
              "problems": []
            }""";

    private final ScriptedChatModel billing = replies("You were charged twice; a refund is waiting in the app.");
    private final ScriptedChatModel technical = replies("Please send the request id of a failing call.");
    private final ScriptedChatModel account = replies("Go to Settings, then Users, then Invite.");
    private final ScriptedChatModel editor = replies("Merged reply", "Revised reply");

    @Test
    void sendsASingleIssueStraightToItsDepartment() {
        var service = service(plan("TECHNICAL"), replies(APPROVED));

        ReplyDraft draft = service.draftReply("502 errors", "Every call to /v1/chat fails since 9:00.");

        assertThat(draft).isEqualTo(new ReplyDraft(List.of(Department.TECHNICAL), "Please send the request id of a failing call.", 1, false));
        assertThat(billing.prompts()).isEmpty();
        assertThat(editor.prompts()).isEmpty();
    }

    @Test
    void answersEachIssueWithItsDepartmentAndMergesTheAnswers() {
        var service = service(plan("BILLING", "ACCOUNT"), replies(APPROVED));

        ReplyDraft draft = service.draftReply("Two things", "I was charged twice, and how do I add a colleague?");

        assertThat(draft.reply()).isEqualTo("Merged reply");
        assertThat(draft.departments()).containsExactly(Department.BILLING, Department.ACCOUNT);
        assertThat(billing.prompts().getFirst().getUserMessage().getText()).startsWith("Answer only this part of the ticket: BILLING question");
        assertThat(editor.prompts().getFirst().getUserMessage().getText())
                .contains("You were charged twice; a refund is waiting in the app.", "Go to Settings, then Users, then Invite.");
        assertThat(technical.prompts()).isEmpty();
    }

    @Test
    void capsTheNumberOfWorkers() {
        ScriptedChatModel everyBilling = new ScriptedChatModel(prompt -> new AssistantMessage("part"));
        var service = new TicketReplyService(client(replies(plan("BILLING", "BILLING", "BILLING", "BILLING", "BILLING", "BILLING"))),
                Map.of(Department.BILLING, client(everyBilling), Department.TECHNICAL, client(technical), Department.ACCOUNT, client(account)),
                client(editor), client(replies(APPROVED)));

        service.draftReply("Many", "Six billing questions");

        assertThat(everyBilling.prompts()).hasSize(TicketReplyService.MAX_ISSUES);
    }

    @Test
    void revisesTheReplyWithTheReviewersProblems() {
        var service = service(plan("BILLING", "ACCOUNT"), replies("""
                {
                  "approved": false,
                  "problems": [
                    "It promises the refund by Friday."
                  ]
                }""", APPROVED));

        ReplyDraft draft = service.draftReply("Two things", "Charged twice; add a colleague?");

        assertThat(draft.reply()).isEqualTo("Revised reply");
        assertThat(draft.rounds()).isEqualTo(2);
        assertThat(editor.prompts().getLast().getUserMessage().getText()).contains("Merged reply", "- It promises the refund by Friday.");
    }

    @Test
    void handsTheReplyToAnAgentWhenTheReviewerNeverApproves() {
        ScriptedChatModel stubbornEditor = new ScriptedChatModel(prompt -> new AssistantMessage("Another try"));
        var service = new TicketReplyService(client(replies(plan("ACCOUNT"))),
                Map.of(Department.BILLING, client(billing), Department.TECHNICAL, client(technical), Department.ACCOUNT, client(account)),
                client(stubbornEditor),
                client(new ScriptedChatModel(prompt -> new AssistantMessage("""
                        {
                          "approved": false,
                          "problems": [
                            "Promises a date."
                          ]
                        }"""))));

        ReplyDraft draft = service.draftReply("Locked out", "I can't sign in.");

        assertThat(draft.rounds()).isEqualTo(TicketReplyService.MAX_ROUNDS);
        assertThat(draft.needsAgent()).isTrue();
        assertThat(stubbornEditor.prompts()).hasSize(TicketReplyService.MAX_ROUNDS - 1);
    }

    @Test
    void needsAWriterForEveryDepartment() {
        assertThatThrownBy(() -> new TicketReplyService(client(editor), Map.of(Department.BILLING, client(billing)), client(editor), client(editor)))
                .isInstanceOf(IllegalArgumentException.class);
    }

    private TicketReplyService service(String plan, ScriptedChatModel reviewer) {
        return new TicketReplyService(client(replies(plan)),
                Map.of(Department.BILLING, client(billing), Department.TECHNICAL, client(technical), Department.ACCOUNT, client(account)),
                client(editor), client(reviewer));
    }

    /** A plan with one issue per department given, each phrased as "DEPARTMENT question". */
    private static String plan(String... departments) {
        return List.of(departments).stream()
                .map(department -> "{\"department\": \"%s\", \"question\": \"%s question\"}".formatted(department, department))
                .collect(Collectors.joining(", ", "{\"issues\": [", "]}"));
    }

    /** Answers with each reply in turn. */
    private static ScriptedChatModel replies(String... replies) {
        Iterator<String> next = List.of(replies).iterator();
        return new ScriptedChatModel(prompt -> new AssistantMessage(next.next()));
    }

    private static ChatClient client(ScriptedChatModel model) {
        return ChatClient.builder(model).build();
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="cost" title="Count the model calls">
A ticket with n issues costs one planner call, n writer calls, a merge when n is more than one, and up to `MAX_ROUNDS` reviews
with a revision between each pair. Two issues, approved in round 2, make seven calls. Cap the fan-out yourself, because the
planner decides how many issues there are, and give simple roles a cheaper model through their own builder.
</Gotcha>

<Gotcha kind="reliability" title="Every loop needs an exit">
A reviewer can keep finding problems. Fix the number of rounds and, when they run out, return the draft with a flag for a
person, as `needsAgent` does, instead of looping or failing the request.
</Gotcha>

<Gotcha kind="security" title="Drafts go to agents, not to customers">
The workflow writes text for a person to check before it is sent. Protect the endpoint with an agent scope, as
`SecurityConfig` does, and test that a customer's token gets `403`.
</Gotcha>

<MoreGotchas>

<Gotcha kind="reliability" title="Parallel calls meet rate limits">
Virtual threads make fan-out cheap, but your provider limits requests and tokens per minute. Many tickets at once multiply the
calls. Keep the fan-out small and handle `429` responses with Spring AI's retry settings. A virtual thread also doesn't inherit
the request's `SecurityContext`, so pass a worker anything it needs as an argument.
</Gotcha>

</MoreGotchas>

## Recap

- Workflows keep the control flow in code; agents let the model choose. Prefer a workflow when you know the steps.
- Orchestrator, routing, parallel workers and evaluator-optimizer are plain Java around `ChatClient` calls: structured output for
  plans and reviews, `builder.clone()` per role and virtual threads for the fan-out.
- Cap the fan-out and the rounds, and hand what is left to a person.
