**You'll need:** the support app from Module 5. The recordings in this lesson come from Lesson 1's Testcontainers setup.

A customer says the assistant gave a wrong answer. Your logs hold the question and the reply. Between them were an advisor
chain, a query rewrite, an embedding call, a vector search, two or three model calls and a tool, and none of it left a trace.
Spring AI already measures every one of those steps. This lesson exports them as OpenTelemetry traces and metrics, then puts a
price on each model call. The first trace we recorded found a bug in the support app that no test had caught.

## 1. Spring mental model

Spring AI wraps each step in a Micrometer observation. With a tracer on the classpath, each observation becomes a span, nested
the way the calls nest:

| Span | One per | Attributes you'll use |
| --- | --- | --- |
| `spring.ai.chat.client` | `ChatClient` call | the advisors, the tool names, the conversation id |
| `spring.ai.advisor` | advisor in the chain | the advisor's name and order |
| `gen_ai.client.operation` | model call, chat or embedding | request and response model, input and output tokens, finish reason |
| `db.vector.client.operation` | vector store call | the query text, top-k, threshold, filter |
| `spring.ai.tool` | tool execution | the tool's name; its arguments and result only if you switch them on |

These rules come from the 2.0.2 and Boot 4.1.2 classes and from running the support app:

- Boot 4 has one starter for this: `spring-boot-starter-opentelemetry`. It brings the OpenTelemetry SDK, the Micrometer tracing
  bridge and OTLP exporters for traces and metrics. The actuator isn't needed.
- Every model call also feeds two metrics: the `gen_ai.client.operation` timer and the `gen_ai.client.token.usage` counter, split
  by `gen_ai.token.type` (`input`, `output`, `total`) and tagged with the operation, the provider and the request and response
  model.
- Boot samples one trace in ten by default (`management.tracing.sampling.probability: 0.1`). Traces are exported only once you
  set `management.opentelemetry.tracing.export.otlp.endpoint`. Metrics go to `http://localhost:4318/v1/metrics` by default.
- Content stays out by default. `spring.ai.chat.observations.log-prompt` and `log-completion` log the messages at INFO, with
  the trace and span id on the log line, not in the span. `spring.ai.tools.observations.include-content` puts each tool's
  arguments and result into the span.
- One piece of content is always recorded: the vector span's `db.vector.query.content` holds the text that was searched for.

For a support assistant, keeping every trace is usually affordable: each request already costs seconds of model time, and the
request a customer complains about is the one you need. Lower it when your trace bill says so.

The trace found the problem in `KnowledgeRagConfig`. `CompressionQueryTransformer` makes a model call for every question, a first
question too. It has nothing to compress then, and a small model can turn the question into nonsense. The `Query` history it
receives is the whole prompt, system message and current question included, so it is never empty. A follow-up is a question
that comes after an answer. Rewrite only those, and on a cheaper model, because rewriting a question is a small job:

<CodeFile title="src/main/java/com/example/support/knowledge/KnowledgeRagConfig.java">
```java {27,31,49}
package com.example.support.knowledge;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.MessageType;
import org.springframework.ai.chat.prompt.ChatOptions;
import org.springframework.ai.rag.Query;
import org.springframework.ai.rag.advisor.RetrievalAugmentationAdvisor;
import org.springframework.ai.rag.generation.augmentation.ContextualQueryAugmenter;
import org.springframework.ai.rag.preretrieval.query.transformation.CompressionQueryTransformer;
import org.springframework.ai.rag.preretrieval.query.transformation.QueryTransformer;
import org.springframework.ai.rag.retrieval.search.VectorStoreDocumentRetriever;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.boot.context.properties.EnableConfigurationProperties;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.Ordered;

@Configuration(proxyBeanMethods = false)
@EnableConfigurationProperties(KnowledgeProperties.class)
class KnowledgeRagConfig {

    @Bean
    RetrievalAugmentationAdvisor knowledgeRagAdvisor(ChatClient.Builder builder, VectorStore vectorStore,
            KnowledgeProperties knowledge) {
        // Turns a follow-up such as "and for gift cards?" into a standalone question, using the history.
        QueryTransformer compression = CompressionQueryTransformer.builder()
                .chatClientBuilder(builder.clone().defaultOptions(ChatOptions.builder().model(knowledge.rewriteModel())))
                .build();
        return RetrievalAugmentationAdvisor.builder()
                // The transformer calls the model for every question, a first one too, and can garble it.
                .queryTransformers(query -> isFollowUp(query) ? compression.transform(query) : query)
                .documentRetriever(VectorStoreDocumentRetriever.builder()
                        .vectorStore(vectorStore)
                        .topK(5)
                        .similarityThreshold(0.5)
                        .filterExpression(KnowledgeFilters.customerDocuments()) // when a call passes no filter
                        .build())
                // An order question finds no documents. The default would then replace it with a refusal, and the model
                // would never call a tool. The system prompt keeps policy answers to the documents instead.
                .queryAugmenter(ContextualQueryAugmenter.builder().allowEmptyContext(true).build())
                // After memory (+ 200), so memory stores the question rather than the augmented prompt,
                // and before tool calling (+ 300), so it retrieves once per question.
                .order(Ordered.HIGHEST_PRECEDENCE + 225)
                .build();
    }

    /** The history is the whole prompt so far, this question included: a follow-up comes after an answer. */
    private static boolean isFollowUp(Query query) {
        return query.history().stream().anyMatch(message -> message.getMessageType() == MessageType.ASSISTANT);
    }
}
```

```java {24,26}
package com.example.support.cost;

import java.math.BigDecimal;
import java.util.Map;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotEmpty;
import jakarta.validation.constraints.NotNull;

import org.springframework.ai.chat.metadata.Usage;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.validation.annotation.Validated;

/** List prices by model name, as the request names the model. */
@Validated
@ConfigurationProperties("support.cost")
public record CostProperties(@NotEmpty Map<String, @Valid Price> prices) {

    /** USD per million tokens. */
    public record Price(@NotNull BigDecimal input, @NotNull BigDecimal cachedInput, @NotNull BigDecimal output) {

        /** The prompt-token count includes the tokens read from the provider's cache, which cost less. */
        BigDecimal of(Usage usage) {
            long cached = usage.getCacheReadInputTokens() == null ? 0 : usage.getCacheReadInputTokens();
            return input.multiply(BigDecimal.valueOf(usage.getPromptTokens() - cached))
                    .add(cachedInput.multiply(BigDecimal.valueOf(cached)))
                    .add(output.multiply(BigDecimal.valueOf(usage.getCompletionTokens())))
                    .movePointLeft(6);
        }
    }
}
```

A cost meter is one more `ObservationHandler`. It sees every model call, the rewrite and each round of the tool loop included,
and tags the spend with the same `gen_ai.request.model` as Spring AI's token metric:

<CodeFile title="src/main/java/com/example/support/cost/TokenCostMeter.java">
```java {33,43,46}
package com.example.support.cost;

import java.util.Map;

import com.example.support.cost.CostProperties.Price;

import io.micrometer.core.instrument.Counter;
import io.micrometer.core.instrument.MeterRegistry;
import io.micrometer.observation.Observation;
import io.micrometer.observation.ObservationHandler;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.observation.ChatModelObservationContext;
import org.springframework.ai.chat.prompt.ChatOptions;

/** Counts what each model call costs, tagged like Spring AI's token metric so the two line up on a dashboard. */
class TokenCostMeter implements ObservationHandler<ChatModelObservationContext> {

    private static final Logger log = LoggerFactory.getLogger(TokenCostMeter.class);

    private final MeterRegistry meterRegistry;
    private final Map<String, Price> prices;

    TokenCostMeter(MeterRegistry meterRegistry, Map<String, Price> prices) {
        this.meterRegistry = meterRegistry;
        this.prices = prices;
    }

    @Override
    public void onStop(ChatModelObservationContext context) {
        ChatResponse response = context.getResponse();
        ChatOptions options = context.getRequest().getOptions();
        if (response == null || options == null || options.getModel() == null) {
            return; // the call failed, or named no model
        }
        String model = options.getModel();
        Price price = prices.get(model);
        if (price == null) {
            log.warn("No price for model {}, so its calls are missing from support.ai.cost", model);
            return;
        }
        Counter.builder("support.ai.cost")
                .description("Model spend at list price")
                .baseUnit("usd")
                .tag("gen_ai.request.model", model)
                .register(meterRegistry)
                .increment(price.of(response.getMetadata().getUsage()).doubleValue());
    }

    @Override
    public boolean supportsContext(Observation.Context context) {
        return context instanceof ChatModelObservationContext;
    }
}
```

```java {32,37}
package com.example.support.cost;

import static org.assertj.core.api.Assertions.assertThat;
import static org.assertj.core.api.Assertions.within;

import java.math.BigDecimal;
import java.util.List;
import java.util.Map;

import com.example.support.cost.CostProperties.Price;

import io.micrometer.core.instrument.simple.SimpleMeterRegistry;
import org.junit.jupiter.api.Test;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.metadata.ChatResponseMetadata;
import org.springframework.ai.chat.metadata.DefaultUsage;
import org.springframework.ai.chat.metadata.Usage;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.chat.observation.ChatModelObservationContext;
import org.springframework.ai.chat.prompt.ChatOptions;
import org.springframework.ai.chat.prompt.Prompt;

class TokenCostMeterTest {

    private final SimpleMeterRegistry meterRegistry = new SimpleMeterRegistry();
    private final TokenCostMeter meter = new TokenCostMeter(meterRegistry,
            Map.of("gpt-5-mini", new Price(new BigDecimal("0.25"), new BigDecimal("0.025"), new BigDecimal("2.00"))));

    @Test
    void pricesCachedInputAtTheCachedRate() {
        meter.onStop(call("gpt-5-mini", new DefaultUsage(10_000, 1_000, null, null, 8_000L, null)));

        // 2,000 new input tokens at 0.25, 8,000 cached at 0.025 and 1,000 output at 2.00, per million.
        // Priced from the token metric alone, all 10,000 input tokens would cost 0.25: 0.0045.
        assertThat(meterRegistry.get("support.ai.cost").tag("gen_ai.request.model", "gpt-5-mini").counter().count())
                .isCloseTo(0.0027, within(1e-12));
    }

    @Test
    void leavesOutAModelWithoutAPrice() {
        meter.onStop(call("gpt-5-nano", new DefaultUsage(10_000, 1_000)));

        assertThat(meterRegistry.find("support.ai.cost").counter()).isNull();
    }

    private static ChatModelObservationContext call(String model, Usage usage) {
        ChatModelObservationContext context = ChatModelObservationContext.builder()
                .prompt(new Prompt("Where is my order 1042?", ChatOptions.builder().model(model).build()))
                .provider("openai")
                .build();
        context.setResponse(new ChatResponse(List.of(new Generation(new AssistantMessage("It has shipped."))),
                ChatResponseMetadata.builder().usage(usage).build()));
        return context;
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="cost" title="A query rewrite you didn't know you were paying for">
`CompressionQueryTransformer` calls the model for every question. In our recording that was one call in three, and on the first
question it searched for the model's reply, "Can you please provide the follow-up query to synthesize into a concise query?",
instead of the question. Look at a trace of each `ChatClient` you build: advisors and transformers can make model calls of their
own, and they show up as nested `spring.ai.chat.client` spans.
</Gotcha>

<Gotcha kind="security" title="The content switches send customer data to your trace backend">
With `include-content`, the `findOrder` span held the order's total, date and tracking number, and the `proposeRefund` span the
refund. `log-prompt` and `log-completion` write the whole conversation into your logs. Turn them on to debug, in one environment,
for a short time. The vector span's query text is recorded whatever you set. The question is redacted by then, because
`PiiRedactionAdvisor` runs before retrieval; Lesson 3 covers the rest.
</Gotcha>

<Gotcha kind="reliability" title="Traces you never get">
Out of the box, Boot keeps one trace in ten, exports none until you set the trace endpoint, and names every service
`unknown_service` until you set `spring.application.name`. When nothing listens on the endpoint, the app logs "Failed to export
spans" and keeps serving.
</Gotcha>

<Gotcha kind="cost" title="The token metric prices cached input as new input">
OpenAI's prompt-token count includes the tokens it read from its prompt cache, which cost a tenth as much. Spring AI reports those
only as the span attribute `gen_ai.usage.cache_read.input_tokens`, not in `gen_ai.client.token.usage`. Dollars computed from the
token metric overstate a cached prompt. `TokenCostMeter` reads `Usage.getCacheReadInputTokens()` instead.
</Gotcha>

<Gotcha kind="cost" title="Read the token counts, don't estimate them">
The same tool loop sent 412 input tokens to the model, then 201 after the tool ran, although the second prompt was longer:
llama3.2's chat template puts the tool definitions only into a prompt that ends with a user message. Templates, tokenizers and
providers all count differently. Budget from `gen_ai.client.token.usage`, not from the length of your prompts.
</Gotcha>

## Recap

- `spring-boot-starter-opentelemetry` turns Spring AI's observations into spans, and its token usage into metrics, exported over
  OTLP. Set the service name, the trace endpoint and the sampling probability.
- One trace shows the advisor chain, every model call with its tokens, the vector search with its query, and each tool.
- Content is off by default. Switch it on to debug, briefly, and remember the vector query text is always there.
- Look for model calls you didn't ask for: the RAG rewrite ran on every question. Rewrite only follow-ups, on a cheaper model.
- An `ObservationHandler` prices each call by model, with cached input at the cached rate, so dashboards show dollars per model.
