A chat model remembers nothing between calls. Every request must carry the conversation so far, and choosing what to carry,
where to keep it and whose it is, is your job. Spring AI 2.1 does it with sessions: a session stores a conversation as events,
and two advisors from the previous lessons load and save them around each call.

## 1. Spring mental model

Session memory works like Spring Session, and the pieces map one to one:

| Spring you know | Spring AI 2.1 | What it does |
| --- | --- | --- |
| `HttpSession` | A session, named by the id you pass with `SessionAdvisors.session(id)` | One user's conversation with the assistant. |
| Spring Session's `SessionRepository` | `SessionRepository` | Stores sessions and their events: in memory, or in JDBC. |
| `SessionRepositoryFilter` | `SessionTurnAdvisor` and `SessionMemoryAdvisor` | Open the turn, load the history before the call and save the new messages after it. |
| `maxInactiveInterval` | `spring.ai.session.time-to-live` | When a session expires: 60 days by default, counted from its creation. |

`SessionService` sits in front of the repository: the advisors use it, and so does your code when it deletes a chat or looks one
up. The session stores every message as an event and never trims it. What reaches the model is chosen per request by an
`EventFilter`: the memory advisor's default, `EventFilter.all()`, sends the whole conversation; `EventFilter.lastN(40)` sends
the newest 40 messages, extended back to the start of a turn so a turn is never cut in half.

These rules come from the 2.1.0 classes and from tests we ran against them:

- Model starters don't configure sessions. Add `spring-ai-starter-model-session-jdbc` for PostgreSQL, MySQL, SQL Server or H2, or
  define a `SessionService` over an `InMemorySessionRepository` yourself, as the first lesson of this module did. The JDBC
  starter creates its tables only for embedded databases unless you set `spring.ai.session.repository.jdbc.initialize-schema`.
- A call without a session id fails with `IllegalStateException: No session ID found in advisor context`, before anything is
  stored or sent.
- Session ids are `VARCHAR(255)` in JDBC, and the session records its creation time, its expiry and metadata you pass when it is
  created.
- System messages aren't stored. `ChatClient` sends your system prompt with every request, so changing it changes every
  conversation at once.
- Memory ordered after `ToolCallingAdvisor`, as `SessionAdvisors` does by default, stores every tool call and tool result. This
  course orders it at `HIGHEST_PRECEDENCE + 210`, before the loop, so a session holds the questions and the final answers.

Spring AI also keeps `VectorStoreChatMemoryAdvisor`, which answers a different question:

| | Session memory | `VectorStoreChatMemoryAdvisor` |
| --- | --- | --- |
| Artifact | `spring-ai-session-advisor`, in the session starter | `spring-ai-vector-store-advisor` |
| Stores | Every message as an event in the session | Each message as a document in a `VectorStore`, tagged with the conversation id |
| Sends to the model | The messages the event filter picks, in order, as real messages | The messages most similar to the question (top 20 by default), as text in the system prompt |
| Good for | Ordinary chat: what was just said | Long histories where something from weeks ago matters |
| Default order | `HIGHEST_PRECEDENCE + 200` (turn), `+ 1000` (memory) | `HIGHEST_PRECEDENCE + 200` |

## 2. Interactive sandbox

<ChatMemoryLab client:visible />

Things to try:

- As Alice, say **My order number is 1042.** Switch to Bob and ask **What is my order number?** With **UUID from user and chat**,
  Bob's conversation is empty. Choose **The chat id from the URL** and repeat: Bob gets Alice's order number.
- Choose **No session id** and send anything. The call fails, and nothing is stored.
- With `lastN(4)`, keep talking. Every message stays in the table, but the model only gets the newest four and forgets the order
  number. Switch to `all()` and it remembers again, at the price of sending the whole conversation every time.

```java {34-37}
package com.example.support.chat;

import java.time.Clock;
import java.util.List;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.SafeGuardAdvisor;
import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;
import org.springframework.ai.session.EventFilter;
import org.springframework.ai.session.SessionService;
import org.springframework.ai.session.advisor.SessionAdvisors;
import org.springframework.ai.vectorstore.VectorStore;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.Ordered;

@Configuration(proxyBeanMethods = false)
class SupportChatConfig {

    @Bean
    ChatClient supportChatClient(ChatClient.Builder builder, SessionService sessionService) {
        return builder
                .defaultSystem("You are the support assistant for Acme Cloud.")
                .defaultAdvisors(
                        SafeGuardAdvisor.builder()
                                .sensitiveWords(List.of("internal only", "api_key"))
                                .order(Ordered.HIGHEST_PRECEDENCE + 25)
                                .build(),
                        new TokenBudgetAdvisor(200_000, Clock.systemUTC()),   // + 50
                        new PiiRedactionAdvisor(),                            // + 100
                        new AnswerLanguageAdvisor(),                          // + 250
                        new SimpleLoggerAdvisor())                            // 0, in the tool loop
                // The turn (+ 200) and memory (+ 210) before the tool loop, so memory runs once per call.
                .defaultAdvisors(SessionAdvisors.builder(sessionService)
                        .memory(memory -> memory
                                .order(Ordered.HIGHEST_PRECEDENCE + 210)
                                .eventFilter(EventFilter.lastN(40)))
                        .build())
                .build();
    }

    @Bean
    ChatClient faqChatClient(ChatClient.Builder builder, VectorStore vectorStore) {
        return builder
                .defaultSystem("Answer questions about Acme Cloud plans and billing.")
                .defaultAdvisors(new PiiRedactionAdvisor(), new SemanticCacheAdvisor(vectorStore, 0.92))
                .build();
    }
}
```

The service builds the session id from the signed-in user and the chat id from the URL. A name-based UUID is the same every
time for the same pair and different for every user, and it keeps the user's name out of the session table and the logs:

<CodeFile title="src/main/java/com/example/support/chat/SupportChatService.java">
```java {25,34,37-39}
package com.example.support.chat;

import java.nio.charset.StandardCharsets;
import java.util.Locale;
import java.util.UUID;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.session.SessionService;
import org.springframework.ai.session.advisor.SessionAdvisors;
import org.springframework.stereotype.Service;

@Service
public class SupportChatService {

    private final ChatClient supportChatClient;
    private final SessionService sessionService;

    public SupportChatService(ChatClient supportChatClient, SessionService sessionService) {
        this.supportChatClient = supportChatClient;
        this.sessionService = sessionService;
    }

    public String ask(String userId, UUID chatId, String question, Locale language) {
        return supportChatClient.prompt()
                .user(question)
                .advisors(SessionAdvisors.session(sessionId(userId, chatId)))
                .advisors(advisor -> advisor
                        .param(TokenBudgetAdvisor.USER_ID, userId)
                        .param(AnswerLanguageAdvisor.LANGUAGE, language))
                .call()
                .content();
    }

    public void forget(String userId, UUID chatId) {
        sessionService.delete(sessionId(userId, chatId));
    }

    /** A session id that only this user's chat maps to, so a chat id alone never reaches another user's session. */
    static String sessionId(String userId, UUID chatId) {
        return UUID.nameUUIDFromBytes((userId + ":" + chatId).getBytes(StandardCharsets.UTF_8)).toString();
    }
}
```

```java {32,38,41}
import java.security.Principal;
import java.util.Locale;
import java.util.UUID;

import jakarta.validation.Valid;
import jakarta.validation.constraints.NotBlank;
import jakarta.validation.constraints.Size;

import org.springframework.http.HttpStatus;
import org.springframework.web.bind.annotation.DeleteMapping;
import org.springframework.web.bind.annotation.PathVariable;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.ResponseStatus;
import org.springframework.web.bind.annotation.RestController;

@RestController
@RequestMapping("/api/chats/{chatId}")
class SupportChatController {

    private final SupportChatService chatService;

    SupportChatController(SupportChatService chatService) {
        this.chatService = chatService;
    }

    @PostMapping("/messages")
    AnswerResponse ask(@PathVariable UUID chatId, @Valid @RequestBody AskRequest request, Principal principal, Locale locale) {
        return new AnswerResponse(chatService.ask(principal.getName(), chatId, request.question(), locale));
    }

    @DeleteMapping
    @ResponseStatus(HttpStatus.NO_CONTENT)
    void forget(@PathVariable UUID chatId, Principal principal) {
        chatService.forget(principal.getName(), chatId);
    }

    record AskRequest(@NotBlank @Size(max = 4000) String question) {
    }

    record AnswerResponse(String answer) {
    }
}
```

```java {43,66}
package com.example.support.chat;

import static org.assertj.core.api.Assertions.assertThat;

import java.util.ArrayList;
import java.util.List;
import java.util.Locale;
import java.util.UUID;

import org.junit.jupiter.api.Test;
import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.messages.AssistantMessage;
import org.springframework.ai.chat.messages.Message;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.model.Generation;
import org.springframework.ai.chat.prompt.Prompt;
import org.springframework.ai.session.DefaultSessionService;
import org.springframework.ai.session.InMemorySessionRepository;
import org.springframework.ai.session.SessionService;
import org.springframework.ai.session.advisor.SessionAdvisors;
import org.springframework.core.Ordered;

class SupportChatServiceTest {

    private final List<Prompt> prompts = new ArrayList<>();
    private final SessionService sessionService = DefaultSessionService.builder()
            .sessionRepository(InMemorySessionRepository.builder().build())
            .build();
    private final UUID chatId = UUID.fromString("0f8e2a4c-6b1d-4c3e-9a7f-5d2b8c1e4a60");

    private final SupportChatService service = new SupportChatService(
            ChatClient.builder(prompt -> {
                        prompts.add(prompt);
                        return new ChatResponse(List.of(new Generation(new AssistantMessage("Noted."))));
                    })
                    .defaultAdvisors(SessionAdvisors.builder(sessionService)
                            .memory(memory -> memory.order(Ordered.HIGHEST_PRECEDENCE + 210))
                            .build())
                    .build(),
            sessionService);

    @Test
    void usersWithTheSameChatIdDoNotShareAConversation() {
        service.ask("alice", chatId, "My order number is 1042.", Locale.ENGLISH);
        service.ask("bob", chatId, "What is my order number?", Locale.ENGLISH);

        assertThat(prompts.getLast().getInstructions())
                .extracting(Message::getText)
                .containsExactly("What is my order number?");
    }

    @Test
    void aUserSeesTheirOwnHistory() {
        service.ask("alice", chatId, "My order number is 1042.", Locale.ENGLISH);
        service.ask("alice", chatId, "What is my order number?", Locale.ENGLISH);

        assertThat(prompts.getLast().getInstructions())
                .extracting(Message::getText)
                .containsExactly("My order number is 1042.", "Noted.", "What is my order number?");
    }

    @Test
    void forgetDeletesOnlyThatUsersChat() {
        service.ask("alice", chatId, "Hello", Locale.ENGLISH);
        service.ask("bob", chatId, "Hello", Locale.ENGLISH);

        service.forget("alice", chatId);

        assertThat(sessionService.findById(SupportChatService.sessionId("alice", chatId))).isNull();
        assertThat(sessionService.getMessages(SupportChatService.sessionId("bob", chatId))).hasSize(2);
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="security" title="A session id from the client is a data leak">
If the id comes straight from the URL or the request body, anyone who learns or guesses it reads that conversation, and two users
who pick the same id share one. Derive the id on the server from the authenticated user, as `sessionId(userId, chatId)` does,
or look up the session and check its owner.
</Gotcha>

<Gotcha kind="cost" title="By default every message is sent, every time">
The memory advisor's default filter is `EventFilter.all()`, so a conversation's whole history goes to the model, and is billed,
with every turn. Set `EventFilter.lastN(...)`, cap the input size as the controller does with `@Size`, and keep memory before
the tool loop, so that tool results aren't stored and sent again. The filter counts messages, not tokens: forty short lines and
forty pasted log files cost very differently.
</Gotcha>

<Gotcha kind="security" title="An expired session lives on until you delete it">
A session expires 60 days after it was created (`spring.ai.session.time-to-live`), but expiry is only a date in the table. The
repository still finds an expired session, the advisors keep using it, and its rows stay until something calls
`SessionService.deleteExpiredSessions`. Spring AI runs no sweep of its own. Conversations hold whatever users typed, so give
users a way to delete a chat, store messages after redaction as in the previous lesson, and schedule the sweep. Module 6 does
both.
</Gotcha>

<MoreGotchas>

<Gotcha kind="reliability" title="The schema is created only for embedded databases">
`spring.ai.session.repository.jdbc.initialize-schema` defaults to `embedded`, so on PostgreSQL the tables don't exist and the
first call fails. Set it to `always`, or, better in production, copy
`org/springframework/ai/session/jdbc/schema-postgresql.sql` from the `spring-ai-session-jdbc` jar into a Flyway or Liquibase
migration and set it to `never`.
</Gotcha>

<Gotcha kind="reliability" title="The app needs its database to start">
The JDBC session repository connects at startup to detect the database dialect. A test context that loads the full
configuration without a database fails before any test runs. `@WebMvcTest` doesn't load it; for `@SpringBootTest`, start
PostgreSQL in Testcontainers, as Module 6 does.
</Gotcha>

<Gotcha kind="migration" title="ChatMemory is deprecated for removal">
`ChatMemory`, `MessageWindowChatMemory`, `MessageChatMemoryAdvisor` and `ChatMemoryRepository` are deprecated for removal since
2.1.0. Replace `MessageChatMemoryAdvisor` with `SessionAdvisors`, `ChatMemory.CONVERSATION_ID` with
`SessionAdvisors.session(id)`, `maxMessages` with an `EventFilter`, and `chatMemory.clear(id)` with `sessionService.delete(id)`.
The sessions live in new tables, so existing conversations aren't carried over, and the 36-character limit of the old
`conversation_id` column is gone.
</Gotcha>

</MoreGotchas>

## Recap

- A `SessionService` stores each conversation as events; `SessionAdvisors` loads and saves them around each call, and the event
  filter decides what is sent.
- Add `spring-ai-starter-model-session-jdbc` for a database, and set `initialize-schema` for anything but an embedded one.
- The session id is mandatory. Derive it on the server from the authenticated user.
- Sessions expire 60 days after creation by default, but an expired session works until `deleteExpiredSessions` removes it.
- `VectorStoreChatMemoryAdvisor` recalls similar past messages from a vector store instead of the recent ones.
