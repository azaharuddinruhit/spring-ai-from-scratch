`ChatClient` is the main API in Spring AI 2.x, and `ChatModel` is the lower-level building block underneath it.
If you've used `RestClient`, the shape will feel familiar.

## 1. Spring mental model

| `RestClient` | `ChatClient` | What it does |
| --- | --- | --- |
| `RestClient.Builder` (auto-configured) | `ChatClient.Builder` (auto-configured, prototype-scoped) | Each injection point gets a fresh builder for you to customize. |
| `.defaultHeader(…)` | `.defaultSystem(…)`, `.defaultAdvisors(…)`, `.defaultOptions(…)` | Settings shared by every request this client sends. |
| `.get().uri(…)` | `.prompt().system(…).user(…)` | Describes a single request. |
| `.retrieve()` | `.call()` / `.stream()` | Chooses blocking or reactive delivery. **Nothing is sent yet.** |
| `.body(String.class)` | `.content()` | The terminal operation that sends the request. |
| `.body(Order.class)` | `.entity(Order.class)` | Maps the response to a Java type. |
| `.toEntity(…)` | `.chatResponse()` / `.responseEntity(…)` | Returns the body together with metadata. |
| `ClientHttpRequestInterceptor` | `Advisor` | Ordered interception of every exchange. |

The four terminal operations differ only in what they return:

- **`.call().content()`** returns a `@Nullable String`, which is the assistant's text.
- **`.call().chatResponse()`** returns the full `ChatResponse`: generations, finish reason, model ID and token `Usage`.
- **`.call().entity(Type.class)`** adds JSON-schema format instructions to the prompt and converts the reply into your record. Module 2 covers this in depth.
- **`.stream().content()`** returns a `Flux<String>` of text deltas. `.stream().chatResponse()` returns a `Flux<ChatResponse>` if you also need metadata for each chunk.

## 2. Interactive sandbox

<ChatClientLifecycle client:visible />

Notice where the auto-registered `ToolCallingAdvisor` sits. Its default order is `Ordered.HIGHEST_PRECEDENCE + 300`, so it wraps
every advisor ordered after it (`SimpleLoggerAdvisor` defaults to order `0`). When the model requests a tool, it runs everything below
itself again, including your logger. Memory advisors are the exception: they default to `HIGHEST_PRECEDENCE + 200`, so they sit
outside the tool loop and run once per call. Modules 3 and 5 build on this.

## 3. Idiomatic Java 25 & Gradle 9 code

This lesson's app drafts replies for support agents. An agent sends in a customer's message and gets back a suggested reply to
edit before sending: as plain text, as a typed record, with its token usage, or streamed while it's written.

Keep the system prompt in a resource rather than a Java string so you can review and version it like any other file.

<CodeFile title="src/main/resources/prompts/reply-style.st">
```text

Write at most 120 words in a calm, plain tone, and answer only what the customer asked.
Never promise refunds, credits or dates: say that an agent will confirm them.
An agent must take over when the customer asks for money back, threatens legal action or wants their account closed.
```

<CodeFile title="src/main/java/com/example/reply/ReplyConfig.java">
```java {17-18}
package com.example.reply;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.client.advisor.SimpleLoggerAdvisor;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.core.io.Resource;

@Configuration(proxyBeanMethods = false)
class ReplyConfig {

    @Bean
    ChatClient replyClient(ChatClient.Builder builder,
                           @Value("classpath:/prompts/reply-style.st") Resource systemPrompt) {
        return builder
                .defaultSystem(systemPrompt)
                .defaultAdvisors(new SimpleLoggerAdvisor())   // logs at DEBUG; see the gotcha below
                .build();
    }
}
```

Records describe both the structured output and the API response. The typed result earns its place with `needsAgent`: the caller
routes the draft on a boolean instead of searching the text for a hint. With pattern matching, the metadata mapping stays compact.

<CodeFile title="src/main/java/com/example/reply/ReplyService.java">
```java {15-18,37,43-44,60}
package com.example.reply;

import java.util.Objects;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.ai.chat.metadata.Usage;
import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.stereotype.Service;
import reactor.core.publisher.Flux;

@Service
public class ReplyService {

    /** needsAgent is true when the system prompt says a person must take over. */
    public record SuggestedReply(
            String reply,
            boolean needsAgent
    ) {}

    public record ReplyWithUsage(
            String text,
            String model,
            int totalTokens
    ) {}

    private final ChatClient chatClient;

    public ReplyService(ChatClient replyClient) {
        this.chatClient = replyClient;
    }

    public String suggest(String message) {
        return Objects.requireNonNullElse(prompt(message).call().content(), "");
    }

    public SuggestedReply structured(String message) {
        SuggestedReply reply = prompt(message).call().entity(SuggestedReply.class);
        return Objects.requireNonNull(reply, "model returned no parsable reply");
    }

    /** One request that returns both the text and the metadata. Calling content() and chatResponse() would cost two requests. */
    public ReplyWithUsage withUsage(String message) {
        ChatResponse response = Objects.requireNonNull(prompt(message).call().chatResponse());
        int totalTokens = response.getMetadata().getUsage() instanceof Usage usage && usage.getTotalTokens() != null
                ? usage.getTotalTokens()
                : 0;
        return new ReplyWithUsage(
                response.getResult().getOutput().getText(),
                response.getMetadata().getModel(),
                totalTokens);
    }

    public Flux<String> stream(String message) {
        return prompt(message).stream().content();
    }

    /** The customer's text is a parameter value, never template text; the Prompt Engineering lesson shows why. */
    private ChatClient.ChatClientRequestSpec prompt(String message) {
        return chatClient.prompt()
                .user(u -> u.text("<message>{message}</message>").param("message", message));
    }
}
```
</CodeFile>

Spring MVC returns a `Flux` as server-sent events when the endpoint produces `text/event-stream`. You don't need WebFlux. The
message travels in the request body, because a customer's words in a query string end up in access logs.

<CodeFile title="src/main/java/com/example/reply/ReplyController.java">
```java {12,36-38}
package com.example.reply;

import org.springframework.http.MediaType;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestBody;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RestController;
import reactor.core.publisher.Flux;

/** Each endpoint takes the customer's message as text/plain and shows one terminal operation. */
@RestController
@RequestMapping(path = "/replies", consumes = MediaType.TEXT_PLAIN_VALUE)
class ReplyController {

    private final ReplyService replies;

    ReplyController(ReplyService replies) {
        this.replies = replies;
    }

    @PostMapping
    String suggest(@RequestBody String message) {
        return replies.suggest(message);
    }

    @PostMapping("/structured")
    ReplyService.SuggestedReply structured(@RequestBody String message) {
        return replies.structured(message);
    }

    @PostMapping("/usage")
    ReplyService.ReplyWithUsage withUsage(@RequestBody String message) {
        return replies.withUsage(message);
    }

    @PostMapping(path = "/stream", produces = MediaType.TEXT_EVENT_STREAM_VALUE)
    Flux<String> stream(@RequestBody String message) {
        return replies.stream(message);
    }
}
```

## 4. Production gotchas & security

<Gotcha kind="cost" title="Every terminal call is a new request">
`.call()` only describes the request. Each terminal method (`content()`, `chatResponse()`, `entity()`) sends it again.
Calling `spec.content()` and then `spec.chatResponse()` pays for two completions and can return two different answers. When you need both
the value and the metadata, use `chatResponse()` or `responseEntity(Type.class)`.
</Gotcha>

<Gotcha kind="reliability" title="SSE streams cut off at the async timeout">
MVC streaming runs as an async request. If a long generation takes longer than `spring.mvc.async.request-timeout` (or the servlet
container's default), the client gets a truncated stream. Reverse proxies cause similar problems: nginx buffers responses unless you disable
`proxy_buffering` or send `X-Accel-Buffering: no`, so tokens arrive all at once.
</Gotcha>

<Gotcha kind="security" title="SimpleLoggerAdvisor writes prompts and answers to your logs">
At DEBUG level it logs the full request and response, including any PII, retrieved documents and tool output. Enable it per environment,
never in production by default. Alternatively, use the three-argument constructor with your own `requestToString` and `responseToString`
functions that redact sensitive fields.
</Gotcha>

<MoreGotchas>

<Gotcha kind="reliability" title="ChatClient.create(chatModel) skips observability">
Clients built with `ChatClient.create(…)` or `ChatClient.builder(chatModel)` bypass the auto-configured builder. That means no Micrometer
observations and no `ChatClientBuilderCustomizer` beans. Inject `ChatClient.Builder`, or use `ChatClientBuilderConfigurer` when you work with several models
(see the next lesson).
</Gotcha>

</MoreGotchas>

## Recap

- Use the injected `ChatClient.Builder` to set the system prompt, advisors and options once, and keep `ChatClient` as a bean.
- `.call()` and `.stream()` choose how the response is delivered. The terminal method sends the request, and each call sends a new one.
- `chatResponse()` gives you usage and finish reasons. `entity()` gives you typed records. `stream()` gives you a `Flux` that MVC can serve as SSE.
- The auto-registered `ToolCallingAdvisor` (`HIGHEST_PRECEDENCE + 300`) wraps advisors ordered after it, such as logging and RAG.
  Memory advisors (`+ 200`) wrap it instead.
